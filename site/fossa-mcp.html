The two writes aren’t a pair

Block adds. Unblock replaces.

DELETE /packages/{locator}/rules is a 404. Unblock is the policy editor’s Save, so its scope of impact is the whole policy and it sits behind a stricter gate.

Detail · the request bodies

What actually goes on the wire.

BLOCK    POST /api/packages/{locator}/rules
         {"policyIds":[…], "versions": "ALL" | ["3.11.1"]}

UNBLOCK  PUT  /api/policies/{policyId}/rules
         [ …bare array of the surviving rule objects… ]
Versioned locator
Rejected. pip+aiofile$1.2.3 as identity would create a rule matching nothing — version scope belongs in the body.
versions: []
Rejected, even though the API accepts it, because the API reads an empty array as every version. Omitting the argument is the clean way to say "all".
Missing rules array
Raises rather than sending [], which would wipe the policy.

Verified live end to end: re-blocking reuses the same ruleId rather than duplicating, and a second unblock correctly does nothing.

5

Gated by scope of impact

13 → 137 tools

Writes need FOSSA_ALLOW_WRITES; destructive needs a second flag alongside it. Neither implies the other, so a half-configured deployment fails closed.

Detail · the gate

Tier follows scope of impact, not the HTTP verb.

WRITE
Create and update. FOSSA_ALLOW_WRITES
DESTRUCTIVE
Deletes; writes that replace state wholesale rather than merging into it; and any endpoint whose target set is a filter rather than a list. FOSSA_ALLOW_DESTRUCTIVE and writes.
ADMIN
SAML, OIDC, roles, service accounts, team membership. FOSSA_ALLOW_ADMIN and writes.
PUT /v2/projects/policy with locators=all
  re-policies an entire organization from one call
  → DESTRUCTIVE, despite the verb being PUT

Neither higher tier implies WRITE; both require it alongside. A half-configured deployment therefore fails closed.

Implemented in src/fossa_mcp/writes.py; require_tier runs before any request is constructed.

Detail · the one worth building on

FOSSA already computes license obligations.

GET /api/revisions/{locator}/todos   — undocumented

Obligations Found:
  Include License      Include Copyright     Include Notice
  State Changes        Give Credit           Include Original
  Disclose Source      Rename

That is the exact judgment fossa-license-review currently reconstructs by hand from license names. Wiring the skill to this endpoint would let it cite FOSSA's own obligation set and spend its effort on the distribution-model cross instead — where the real judgment lives, since the same GPL-3.0 is a shipping blocker in a distributed binary and a non-event in a SaaS backend.
